## 2. Key Reconciliations & Reporting Rules

1. **Why Q-Learning has two different delivery rates (`92.4%` vs. `57.8%`):**
   - **`92.4%` (Same-Map Historical Single-Order, `q_learning/q_learning_pipeline.py`):** Trained for 5,000 episodes (1 seed) on `map_seed=0` (80/20 split) and evaluated on the **same fixed hotspot map (`map_seed=0`)**.
   - **`57.8% ± 14.0%` (Unseen-Map Controlled Part A Comparison, `compare/part_a_comparison.py`):** Trained for 60,000 steps across 5 seeds (`11, 22, 33, 44, 55`) on `map_seed=0` (64/16/20 split) and evaluated on an **unseen hotspot map (`test map_seed=202`)**.
   - Always label both explicitly as **"same map (`map_seed=0`)"** vs. **"unseen map (`train map_seed=0 -> test map_seed=202`)"**.
2. **Three Data Splits (Never Merge Silently):**
   - **`80/20` (`shared.split_orders`, seed 42):** Used by historical single-order scripts (`q_learning_pipeline.py`, `dqn_v1..v3.py`, `d3qn_pipeline.py`, `evaluate.py`, `analyze_errors.py`, `app.py`). Hyperparameters in those scripts were selected using the 20% test trips (a documented limitation).
   - **`64/16/20` (`dqn/experiments.split_orders_three_way`, seed 42):** Preserves the exact same 20% test rows as `80/20`, and splits the remaining 80% development set into 64% train and 16% validation (`seed=43`). Used by `compare/part_a_comparison.py` and `dqn_dynamic/`. Because the 20% test partition was previously inspected in historical work, it is held out from new tuning but is not a pristine never-seen test set.
   - **`70/15/15` (`env_multi.split_orders_3way`, seed 42):** Used by all multi-order scripts (`d3qn/*_multi.py`). Architecture selection (Stage A), hyperparameter random search (Stage B), and ablations use validation trips (`seed_offset=1000`) only; test trips (`seed_offset=0`) are evaluated once in Stage C.
3. **Timeout Target Rule:**
   - `compare/part_a_comparison.py` treats timeout truncation as terminal (`done = terminated or truncated`).
   - All `d3qn/*_multi.py` and historical single-order scripts treat only full delivery as terminal (`done = float(terminated)`), continuing value bootstrapping across step-limit cutoffs.
   - Do not pool numbers across the two rules.
4. **On-Time Percentage Is a Benchmark Proxy:**
   - Simulator elapsed minutes use an assumed `2.0 min/step` base clock plus traffic/weather/hotspot multipliers (`env.py`, `env_multi.py`). Comparing simulated minutes against an order's recorded `Time_taken` measures a **relative benchmark proxy**, not real-world road SLA compliance.
5. **Naming Rule:**
   - Always write **Part A / Part B** (never "Phase 1 / Phase 2").
   - Always write **D3QN** for **Dueling Double DQN**, and **Double DQN** for the non-dueling Double-Q network.
